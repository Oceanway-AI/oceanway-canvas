# 新 Studio 改造需求

日期：2026-11-07。需求边界已确认，详细实施顺序见逐步实施计划。首批身份与画布持久化已实现并通过隔离测试，真实登录及完整平台替换尚未验收，见[首批实施记录](../plans/oceanway-studio-first-milestone.md)。

## 已确认的产品决定

1. `Oceanway-AI/oceanway-canvas` 是新 Studio 唯一代码基础。
2. 原 Studio 全部放弃，只保留可复用的视觉元素。不继承旧代码、功能设计、架构、数据库、任务机制、历史 AGENTS 约束或部署方案。
3. 不迁移旧 Studio 业务数据，不建立新旧双轨或兼容层。
4. 保留新项目全部创作功能，包括画布、基础生成、Agent、短剧、剪辑、3D、素材组织、技能及创作类插件。
5. 保留新项目自带 Agent。OceanWay 独立 Runtime 已放弃，不接入、不恢复。
6. 使用 Platform 发布的 `platformclient` 替换新项目的平台层能力。

“全部创作功能保留”是产品范围，并不意味着平台当前已经支持全部模型、音频、第三方工作流或插件协议。缺口必须显式列出和解决，不能擅自裁掉创作功能，也不能绕过 Platform 直连供应商。

## 架构边界

浏览器 → 新项目 Go 业务后端 → platformclient → 用户指定的 Platform 服务。

新项目自带 Agent 的模型调用同样进入 Go 后端的平台接入边界；自带 Node Agent 进程/容器不等于已经放弃的 OceanWay Runtime。

Studio 保留项目、画布、分镜、角色、剪辑时间线、Agent 会话/审批、创作任务编排、产品访问控制和业务关联。Platform 负责平台身份、账号/工作区上下文、模型发布、执行授权、模型执行、价格与资金、统一素材相关服务。SDK 是服务端客户端，不是数据库、任务调度器或可替换整个后端的框架。

资产入口保留 OAC 原生素材库的排布、媒体卡片、标签和档案抽屉。创作和画布复用原生素材选择器；统一账号素材与访问权限通过 Platform 接入，不另设素材库页面。

## 平台能力替换清单

| 能力 | 新项目现状（源码/文档） | 目标需求 |
| --- | --- | --- |
| 身份与会话 | 自有注册、登录、密码找回、第三方登录、用户表和会话 | 以 Platform 身份和会话为权威；保留产品用户引用与创作偏好；登录入口按正式域名与已发布契约设计 |
| 权限 | 本地管理员、用户组、功能开关 | 平台身份/角色与 Studio 资源授权分层；不能把平台成员资格直接当作画布访问权 |
| 模型目录 | 自有渠道、逻辑模型、协议和售价管理 | 从 Platform 目录取得可用模型与能力；Studio 负责创作参数界面，不维护另一套供应路由与价格权威 |
| 调用凭据 | 系统渠道、用户自定义 API Key、前端模型中转路径 | 产品凭据仅在服务端；移除可绕过平台的用户 Key、渠道和直连入口 |
| 普通生成 | 自有任务准入、provider 执行、媒体恢复 | 保留业务任务与前端交互，按平台契约取得授权、提交、查询和关联结果 |
| Agent 生成 | 自带 Agent、审批、工具、媒体任务与文本模型调用 | 保留原生 Agent 编排；规划、对话、工具生成、后台分析等所有收费模型调用统一走平台 |
| 费用与支付 | 本地积分、订单、充值、支付插件、兑换码、退款及计费协调 | 删除第二套资金执行链；消费预估、实际计费和退款以平台为准；账户操作进入平台已有入口 |
| 素材与存储 | 产品素材库、本地媒体目录、OSS/COS、自有配额 | 保留素材浏览、业务分类和引用体验；通过平台素材契约衔接原件、版本、容量与授权；转码等临时工作文件与持久原件分开 |
| 管理后台 | 账号、支付、渠道、模型、存储和内容运营混合 | 删除被平台接管的管理入口及后端写路径；保留新项目需要的内容、技能、创作配置与运行管理 |
| 插件 | 创作/应用插件与模型/支付协议插件混合 | 保留创作能力；涉及供应商执行、支付或账号权威的插件按平台边界改造，不能一刀切删除全部插件 |
| 视觉 | 上游“影策”品牌和现有组件 | 新品牌为 OceanWay Studio；仅参考旧 Studio 的 Logo、色彩、字体、图标和视觉质感，组件布局/交互以新项目为基础 |

## 必须覆盖的行为

- 登录、退出、身份失效和账号切换正确；不同账号/工作区的业务数据、缓存和素材权限隔离。
- 模型选项、能力、参数与最终执行一致；不再从本地渠道表决定供应商。
- 首页、画布、工作台、短剧流水线和 Agent 内部调用均纳入平台替换，避免遗漏隐藏执行路径。
- 业务任务与平台授权、请求和结果建立稳定关联。断网、页面关闭、Worker 重启和结果保存失败的处理以当前平台契约重新设计，不搬用旧 Studio 实现。
- SDK 不负责自动重试 POST；未知执行结果不得被业务层误当作未执行而再次扣费。流式取消与非流式恢复分别按实际能力设计。
- 删除/重试/审批/并发编辑仍维持新项目原有合理业务语义；平台权限和计费拒绝必须正确传达。
- 素材引用、生成结果、分享、下载、剪辑输入/导出和 3D 产物逐项核对；不能只验收图片上传。
- 已被替代的本地平台能力应真正退出路由、配置、运行链和新库初始化，不仅隐藏前端菜单。
- 上游 LICENSE、NOTICE 与第三方许可保留；视觉换标不删除来源声明。

## 源码证据与接入位置

- 根 `AGENTS.md`：Vite/React 前端，Go/Gin/GORM 后端，SQLite/PostgreSQL 与 Redis，自带 Node Agent。
- `web/src/router.tsx`：创作、账号、渠道、模型、充值、兑换码、存储和后台入口。
- `backend/internal/app/service.go`：组合根，持有 auth、payment、业务 worker 与 Agent 服务。
- `backend/internal/app/auth_bridge.go`：登录注册、会话、第三方登录及积分等耦合点。
- `backend/internal/app/task_creation.go`：模型解析、能力检查、额度与任务准入，存在自定义渠道及前端文本路径。
- `backend/internal/app/task_execution.go`：文本/图片/视频/音频任务分派至 provider。
- `backend/internal/app/task_billing.go`：本地订单结算、退款与不确定状态协调，需要由平台资金权威替换。
- `backend/internal/app/provider*.go`、`cloud_agent*.go`、`backend/agent-runtime/pi/`：后续逐条盘点普通生成、内部文本和 Agent 调用。
- 注意：新项目 `backend/internal/platform` 是其本地 worker/协调模块，不是 OceanWay Platform。不可仅按目录名整体删除。
