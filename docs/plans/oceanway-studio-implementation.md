## 目标与实施规则

以 oceanway-canvas 为唯一基础，保留全部创作功能和自带 Agent，通过 Go platformclient 替换平台能力。旧 Studio 仅提供视觉参考；不迁移其代码、数据、架构或历史约束；不引入已放弃的 OceanWay 独立 Runtime。

- 每个步骤形成可独立审查的提交或 PR，记录修改路径、执行过的验证、未覆盖项和阻塞项。阶段完成以行为证据为准。
- 开发中的阶段性闭环不等于全部产品可发布。全部创作功能是最终验收范围，不把缺少平台能力的功能静默删除。
- 每条执行链切到 Platform 时，同步撤出该链的本地扣款、退款、供应商选择和自动重发；没有成功时回退旧 provider 的双轨开关。
- 保留新项目业务队列、任务调度、Agent 编排与必要本地计算；`backend/internal/platform` 是上游本地协调模块，不能按名称整包删除。
- 平台原件存储与本地转码缓存、临时文件分开。业务数据仍由 Studio 持有，SDK 不代替业务数据库。
- 本机只改 Studio 消费端。发现 Platform 缺口时形成接口需求及证据，不自行开发、启动 Platform 或网关。
- 前期使用独立测试库和 HTTP 契约夹具。服务启动、线上联调、付费生成与部署按用户指定范围执行。

## 阶段依赖

主执行顺序：P0 盘点与契约 → P1 SDK 边界 → P2 身份 → P3 模型与预估 → P4 素材 → P5 普通生成 → P6 Agent → P7 全部创作流程 → P8 旧平台层清除 → P9 全面验收与发布。

视觉适配 V1 可在 P2 后独立推进，在 P9 前完成；不以视觉改造阻塞核心执行链。P8 是最终清扫，相关旧运行路径从 P2 起逐条退出。

按最小依赖，P3 与 P4 都依赖 P2，但彼此不强制等待；P5 的纯文本步骤只依赖身份、模型和执行记录合同，参考媒体生成还依赖 P4。P7 的纯编辑/渲染素材适配可在 P4 后推进，依赖 Agent 的流程必须等待 P6。此处是工作依赖，不要求同时启动多个 Agent。

| 顺序 | 阶段 | 用户可见的完成结果 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| 1 | P0 契约与调用盘点 | 功能范围、平台缺口和数据归属明确 | 每个入口有归属，缺口有对应步骤 |
| 2 | P1 SDK 与配置 | 后端能按正确身份访问平台 | 应用注入与会话/Worker 凭据隔离通过 |
| 3 | P2 身份 | 平台登录后创建、保存、重新打开画布 | HTTP、实时连接、分享和账号切换通过 |
| 4 | P3 模型与预估 | 所有创作入口展示平台模型和参数 | 展示、提交、报价版本和付款主体一致 |
| 5 | P4 素材 | 上传、素材库、引用与下载可用 | 原件、版本、权限、容量和删除引用通过 |

## P0：形成完整调用地图与能力合同

1. 将页面、后端 API、Worker、Agent 工具、插件映射到实际模型调用和存储路径，覆盖首页、画布、图片/视频工作台、短剧、电商、音频、字幕、剪辑、3D、技能和导入分享。
2. 将功能分为纯产品逻辑、平台能力、外部依赖三类；分别列出保留、替换、删除的具体路径。
3. 核对实际 Platform 服务版本与 SDK 发布版本，记录 tag、commit、Go 校验值及契约来源。工作区已固定 rc.5，但不预设线上已匹配；发现不匹配时先明确可用合同，再调整锁定版本。
4. 建立能力矩阵：身份/角色、个人/团队、模型类型、输入参数、文本流式、图片编辑、视频、音频、素材、第三方工作流、非模型处理。每项记录 SDK 方法、部署支持、测试证据和缺口。
5. 确定新 Studio 空库初始化方案、业务用户/工作区引用、数据库和 Redis 使用边界；不复用旧 Studio 数据库。默认沿用新项目生产 PostgreSQL/Redis 架构，开发数据库支持范围显式记录。

产物：功能与调用清单、平台能力矩阵、数据归属表、SDK 锁定清单、验收场景清单。

调用清单至少包含：入口/按钮、HTTP 路由、服务函数、后台任务或 Agent 工具、实际出站路径、鉴权主体、资金路径、持久原件位置、平台方法、关联测试、实施步骤和状态。不能只列目录名或只检索页面上的“生成”按钮。

数据归属需先定清楚四个关联：平台用户/工作区与产品用户及项目；产品模型视图与平台模型；业务任务/Agent 步骤与执行授权/原请求；产品 resource 与平台 asset/version。字段名字由实现决定，唯一约束、生命周期和失败恢复先成文，不从旧 Studio 复制表结构。

完成标准：每个外部调用和资金/身份写入口均有归属；无法支持的能力有明确缺口记录。平台 URL、产品身份、域名/Origin、凭据配置位置在联调前落实。缺口只阻塞依赖它的步骤，其他步骤可使用契约夹具推进。

## P1：建立 Go SDK 接入边界

1. 在 `backend/go.mod` 固定 SDK；按需要 vendor 独立模块，不依赖 Platform 根应用或本机 checkout。核对 Go 工具链要求。
2. 在 `backend/internal/` 新建职责明确的 `platformintegration` 包，承载客户端初始化、可信会话上下文、错误映射和产品契约转换；不添加任意 URL/Header 的通用逃生接口。
3. 从 `backend/internal/app/service.go` 注入平台客户端，接通 `backend/cmd/server/main.go` 的实际启动路径，配置固定服务 origin、product、服务端 product key、允许的 session host/origin。SDK 配置缺失时拒绝相关能力，不回退本地账号/provider。
4. 建立会话请求与 Worker 执行上下文隔离；Cookie 更新逐项透传，凭据脱敏，禁止自动跳转泄漏及 POST 传输重试。

完成标准：隔离 HTTP 夹具验证身份请求、执行请求的凭据边界、错误和超时传递；浏览器构建产物不含产品密钥。新增包测试及依赖编译通过。

## P2：替换身份、会话与授权

1. 改造 `backend/internal/handler/auth.go`、`app/auth_bridge.go`、当前用户解析和 `web/src/services/api/auth.ts`，采用已发布登录/回跳机制。当前 `currentUser` 只把本地 Cookie 值传给 service，须改为请求级可信上下文，不能只替换 Cookie 名。
2. 用户表收敛为平台用户引用与产品资料；平台角色负责产品管理资格，Studio 自己校验项目、画布、分享和任务访问权。
3. 按 P0 合同处理工作区及成员身份，保持个人/团队上下文一致，不把团队请求降级为个人付款或个人素材。
4. 移除自有注册、密码找回、账号密码验证、第三方账号登录、默认管理员和注册赠送积分运行入口；保留业务导入能力，不能因其位于 auth 包而误删。
5. 账号切换清理或隔离查询缓存、本地草稿和媒体访问状态；游客/公开分享按新项目现有业务语义单独授权。
6. 单独替换 `handler/canvas_realtime.go` 的周期身份检查及 `auth_profile.go` 的资料入口；核对 WebSocket/SSE 断线后的身份失效和 Cookie 更新方式，不尝试在已升级的连接上更新 HTTP 响应头。

完成标准：登录回跳、刷新、退出、会话过期、无权限、两账号隔离及工作区切换通过；旧登录写路径无法创建第二套账号。可进入并保存空白项目/画布。

## P3：平台模型目录、参数与消费预估

1. 替换本地渠道/逻辑模型目录的数据源，保留新项目模型选择组件及创作参数体验。
2. 定义平台目录到产品模型视图的映射，保留原模型标识、能力、参数 schema、默认值和价格版本，避免产品别名改变执行对象。
3. 提交前在服务端重新核验模型与能力；将预估价格、资金约束与真正执行区分，不在 Studio 重新计算权威售价。
4. 撤出用户 API Key、自定义供应商地址和本地渠道编辑入口；确认前端文本直连/中转路径也不能绕过。

完成标准：模型选择、参数和服务端执行目标一致；目录变化、过期报价、不支持参数和余额/权益不足有明确处理；所有创作入口可取得模型，不使用本地渠道兜底。

## P4：统一素材与业务引用

1. 明确平台 asset/version/project 引用与 Studio resource ID、画布节点、分镜角色和剪辑片段的关联，不把签名 URL 当长期身份。
2. 接入上传、列表、元数据、版本、下载与容量；保留原素材卡片、分类、搜索、收藏等交互，并标明哪些元数据归产品保存。
3. 将生成参考素材与 Worker 读取绑定到有权访问的主体；覆盖多媒体、大文件、分片/中断恢复和跨账号拒绝。
4. 改造本地/OSS/COS 持久原件路径；本地仅保留必要临时处理文件。删除语义按平台引用/claim 合同实现，不能删除其他产品仍引用的原件。
5. 确定导入、只读分享、下载、3D 文件和剪辑输入/导出的资源访问方式。

完成标准：上传 → 刷新 → 引用 → 下载形成闭环；素材权限、容量拒绝、删除引用冲突及重复回填有测试。后续生成可直接使用这套引用。

## P5：普通生成端到端替换

### P5.0 先落实任务与执行合同

在新增提交入口前，给 `model/models_task.go`、repository、任务准入/Worker 和结果保存确定一致合同：

| 情况 | 需要保存或确认的事实 | 允许的后续动作 |
| --- | --- | --- |
| 提交前 | 业务任务、主体、模型/参数/素材、平台授权与原请求身份的持久关联 | 完成准入后按唯一派发规则提交；关键绑定保存失败时不发送 |
| 发送后响应丢失 | 请求可能已被接受，不能只凭网络错误推断未执行 | 按平台提供的原请求查询能力处理；不新建一次收费调用 |
| 平台仍在执行 | 平台返回的原执行标识与状态 | 产品更新进度，沿原标识查询；不增加供应商轮询器 |
| 已有生成结果、素材保存失败 | 原结果及保存操作身份 | 继续完成同一结果的保存和业务关联 |
| 明确拒绝、失败或取消 | 平台明确回执及费用事实 | 如实展示；新重做请求与原请求恢复区分，Studio 不自行补造退款 |
| 并发重试/重复消息 | 唯一业务绑定和结果版本 | 幂等回填；通过事务、唯一约束及现有协调机制避免重复派发 |

这是待落实的行为合同，不预先编造 SDK 未提供的状态字段。需覆盖“授权已发但本地记录失败”“提交成功但未记录响应”等非原子边界；没有可靠查询/去重合同的能力记为阻塞。

`task_creation.go` 当前创建本地计费订单并绑定 `BillingOrderID`。P5 每接入一种生成，都必须同时替换其准入、计费、执行、恢复、取消和结果保存，不能只换 `provider` 请求 URL。每种生成使用夹具记录提交次数与本地资金写入次数，验证故障恢复不会产生额外提交或本地扣退款。

### P5.1 先打通文本

改造 `task_creation.go`、`task_execution.go`、`provider_text.go` 等实际入口，建立业务任务与平台授权/请求的持久关联。分别实现非流式提交/恢复及流式事件/取消，保留现有页面任务交互。

完成标准：一次文本生成及刷新读取成功；断线或 Worker 重启恢复不会自动创建第二笔不确定调用；流式取消不伪造退款。

### P5.2 图片闭环

实现模型选择 → 参考素材 → 平台预估/授权 → 提交 → 原结果查询 → 素材关联 → 画布/历史回填。覆盖无参考图、图片编辑、多产物和原生参数差异，按平台实际能力执行。

完成标准：至少一条真实允许的图片链路可验收；夹具覆盖超时、提交后响应丢失、结果保存失败、并发请求、节点删除和重复回调；同一原结果可重复回填且不会重新计费生成。

### P5.3 视频与其他已支持媒体

接入视频原生提交/查询和结果关联，不复制供应商轮询器；音频按 P0 能力合同接入，缺口转入 P7 清单。保留产品任务进度与取消语义，不声称平台不支持的操作成功。

共同改造：当前链路的 `task_billing.go`、本地额度准入及失败退款退出执行；产品只展示平台返回的费用事实。并发、失败及未知状态规则形成书面状态表，以当前新项目和平台契约设计，不搬运旧 Studio 状态机。

阶段完成标准：首页、画布和工作台使用同一平台执行边界；任务有证据可恢复、结果可追溯、无本地二次扣费、无供应商回退。P5 是首个完整技术闭环，不等于可宣告全功能替换完成。

## P6：保留并接通新项目自带 Agent

1. 保留 `backend/agent-runtime/pi/` 与当前 Agent 服务拓扑，改造 `cloud_agent_pi_model.go` 模型桥。
2. 覆盖会话、规划、上下文压缩、结构化修复、后台分析和全部媒体工具；核对每个隐含模型调用。
3. 逐项审查现有 `cloudAgentModelStepRetries` 等重试：传输结果未知先按原身份恢复；明确的新推理步骤与重试原步骤必须区分，不能用重试次数掩盖重复收费。
4. 保留工具 schema、审批、会话事件、断线重连和画布修改；审批的模型、参数、素材及预算与最终执行绑定，改变后按原业务规则重新确认。
5. 授权到期、撤销、用户退出和后台运行的关系按平台契约处理，Worker 不复用浏览器 Cookie。

完成标准：对话 → 工具审批 → 生成 → 写入画布 → 刷新/重启恢复全链路通过；上下文压缩、拒绝审批、取消、余额不足及多工具并发均有专项验证。Agent 无独立供应商密钥或绕过平台路径。

## P7：完成全部创作场景的平台接入

逐项完成，不以普通画布验收代替：

| 子步骤 | 保留的产品能力 | 必须核对的接入点与验收 |
| --- | --- | --- |
| P7.1 短剧 | 小说改编、拆集、角色/道具/场景、分镜、连续视频 | 内部文本和所有媒体调用；角色素材稳定引用；多段执行、尾帧引用、单段重做与恢复 |
| P7.2 电商与专用工作台 | 产品理解、策划、创意方向、模板 | 后台指定模型、识图、内部分析、批量生成均经平台；原操作流程不退化 |
| P7.3 音频与字幕 | 原音频能力、转写、字幕编辑 | 明确文本/音频端点与材料支持；当前 `transcription_whisper.go` 直连自建 whisper.cpp，属于独立模型执行，须单列平台合同，不当作普通 FFmpeg 计算跳过 |
| P7.4 剪辑 | 时间线、修剪、字幕、预览与成片导出 | 纯本地 FFmpeg 等计算继续由产品处理；输入读取及输出持久化平台化；如有非模型收费先确认平台合同，不自建积分 |
| P7.5 3D | 场景、角色、机位、动画、白模/深度导出 | 模型文件/贴图/视频资源生命周期；导出作为后续生成参考；模型辅助功能走平台 |
| P7.6 技能、插件、导入与分享 | 技能内容、创作插件、第三方画布导入、公开分享 | 区分内容/编辑器插件与供应商/支付插件；第三方工作流及专用供应商资源有明确平台替代；分享不泄漏私有素材 |

完成标准：P0 功能清单逐项有证据。缺失平台支持的项目单列阻塞及所需合同，最终全功能发布前闭环；不能标注“已保留”但实际无法生成。

## P8：清除重复平台能力与建立新产品初始化

1. 删除无调用的本地认证、支付、兑换码、积分、供应商渠道/路由及平台存储配置代码，关联页面、API、后台任务、定时器、插件可执行程序和配置一起处理。
2. 保留内容运营、技能/提示词、产品运行管理和创作配置；资金和账号管理入口按实际平台 URL 跳转。
3. 新建空库初始化只创建必要业务表及平台引用，不初始化第二套钱包/用户密码/渠道种子。重新梳理新项目自己的迁移历史，禁止为了空库启动先运行全部旧平台表迁移再假装删除完成。
4. 清理无用依赖、环境变量、容器、支付构建目标与过时测试；增加“旧入口不可达、不能直连、不能二次扣费”的回归覆盖。
5. 更新 OpenAPI、数据库文档、Compose、部署说明和运维配置。保留许可证与 NOTICE，不恢复旧 Studio 的部署方案。
6. 将安装脚本、Release 来源、Web/Backend/Agent 镜像和 Host Updater 的仓库指向 OceanWay 自有制品。现有 `install-server-image.sh`、`docker-compose.deploy.yml` 和 `internal/hostupdate/manager.go` 仍包含 ddcat-ai 默认来源；改造后不能通过在线更新被上游未改造版本覆盖。只改品牌文字不算完成发布改造。

完成标准：空库启动与必要业务升级测试通过；代码引用、路由、构建产物与实际请求四方面确认旧平台层退出。现有新 Studio 业务数据在后续版本升级中仍可正常演进，不以“不迁移旧 Studio”为由破坏新业务数据。

## V1：OceanWay 视觉适配

1. 仅从已提取参考中选择 Logo、字体、色彩、图标和视觉质感；不复制旧布局/业务组件。
2. 将视觉映射到新项目已有 token、主题及组件层，覆盖明暗主题、品牌名、favicon、空态和主要工作区。
3. 核对首页、画布、Agent、素材、短剧、剪辑和 3D 的一致性及可用性；保留上游法务来源。

完成标准：真实页面桌面与窄屏关键流程通过，明暗主题、焦点、弹窗和画布对比度可用；不以独立原型替代真实页面验收。

## P9：集成验收与发布

1. 运行与变更匹配的后端/前端/Agent 测试、数据库和契约测试；提交推送前按 AGENTS 要求运行 `bun scripts/verify-before-push.mjs`。
2. 在用户指定测试服务上核对真实身份、目录、素材、生成和费用。付费场景记录模型、次数、预算与实际结果；未执行项不得标记通过。
3. 完成两账号/工作区隔离、并发、关页、断网、Worker 重启、平台拒绝、授权过期、原结果重复回填等故障验收，以及 P7 全功能回归。
4. 固定 Studio 镜像与 SDK/平台兼容版本，检查健康探针、日志脱敏、任务诊断和备份。发布回退只回到已验收的新 Studio 版本，不恢复旧 Studio 或独立 Runtime。
5. 用户指定服务器、域名、资源与切换范围后，部署新 Studio，执行入口验收；旧线上资源退场按实际清单单独执行，不从本机归档推断线上已停用。

完成标准：功能矩阵无未解决的发布阻塞，部署与真实流程证据齐全，资金只由平台处理，旧 Studio 和独立 Runtime 不在依赖图中。

## 后续开发批次

1. **目录与素材批次（P3、P4）**：先模型视图，再素材身份/上传/读取/业务引用；有了主体和稳定素材引用后再开始参考媒体生成。
2. **普通生成批次（P5）**：执行记录合同 → 文本非流式 → 文本流式 → 图片生成/编辑 → 视频 → 相关恢复与资金故障验收。各入口最终共用同一服务端边界。
3. **Agent 批次（P6）**：模型桥与压缩 → 工具/审批 → 媒体执行 → 并发、重启与未知结果处理。纠正工具参数的新推理调用不能伪装成免费恢复。
4. **全场景批次（P7）**：按子步骤逐项验收；平台缺口在 P0 即提出，不能等到此阶段才第一次发现。
5. **退场与视觉批次（P8、V1）**：逐链退出的最后清扫、新业务库初始化、环境/构建清理、OceanWay 视觉映射。
6. **发布批次（P9）**：平台真实合同核验、全量相关回归、制品构建、部署配置与正式入口验收。

## 验证执行口径

- P1/P2 优先跑触及包的 Go 专项测试，例如在 `backend/` 运行 `go test ./internal/platformintegration`；身份路由和数据库另加对应专项，不用 SDK 包测试冒充应用接入测试。
- 任务/Agent 夹具统计真实提交次数，覆盖结果未知、重复消息、租约接管、断线与回填失败；数据库与 Redis 相关测试记录是否实际执行，跳过不算通过。
- 前端使用 `web/package.json` 中现有 `typecheck`、`test`、`lint` 和构建命令，按变更选择范围；涉及 Agent 进程补原生桥接测试，涉及 3D 交互补现有预演 E2E。
- 每阶段写入已执行命令、结果、证据位置、环境及未测项。推送前执行仓库规定的 `bun scripts/verify-before-push.mjs`，发布前补实际镜像/Compose 和全功能场景验证。
- 首批已执行后端专项、前端专项/类型检查/构建及真实前端路由的浏览器夹具验证，命令、覆盖范围与未测项记录在[首批实施记录](oceanway-studio-first-milestone.md)。
